Rust 是静态类型语言, 正常情况下, 编译后变量类型并不会丢失. 但如果将不同类型装到 dyn Trait 时:

在这之后, a 和 b 对于编译器来说都是 Box<dyn Display> 了, 原始类型 i32 和 &str 就丢失了, 此时 a 只能调用 Display 的方法, 而不能当作 i32 来用了.

由于每个类型在编译期会生成唯一的 TypeId 代表其原始类型. 因此 core::any::Any trait 的思路就是利用这个 TypeId, 在编译期类型被擦除后, 运行时安全地找回原始类型.

TypeId 本质是一个 Hash 值, 如果不加上 'static 约束的话, 不同生命周期会带来不同类型签名, 比如:

  • &b 对应的是 &'b i32
  • 两个都是 &i32, 但由于生命周期不同, 不能等价, 也就不能得到唯一的 TypeId

因此编译器直接一刀切, 对生命周期不确定的类型都不给 TypeId.

dyn 关键字

dyn 在 Rust 中用于实现动态分发 (dynamic dispatch), 声明的对象是一个 trait object. 其告诉编译器, 这个变量指向的类型在编译期不确定, 需要在运行时通过虚函数表 (vtable) 来查找具体用法.

本质

&dyn Trait 在内存中是一个 fat pointer (16 bytes), 包含两个指针 (各 8 bytes):

  • data_ptr, 指向实际数据 (堆/栈)
  • vtable_ptr, 指向一个虚表

因为 dyn Trait 是编译期大小未知的, 编译器不知道具体的类型, 也就无法确定它有多大. 因此使用的时候都得用引用 (胖指针的大小是确定的).

volatile 语义的方法

volatile 一词的本意是 “易变的, 挥发性的”. 其描述了硬件寄存器的行为:

在编译器默认的世界观里: 我写的代码会唯一改变内存里的东西, 只要我没写, 值就不会变.

而 volatile 会告诉编译器: 这块内存是 “易变的”, 外部世界 (硬件, 中断处理程序, 另一个核心) 随时可能改变它.

volatile 让编译器知道, 你不能假设这块内存是不变的. 体现在具体行为上, 就是让编译器不去优化这行代码.

expect 方法的语义

expect 这个词直译是 “预期, 期望发生” 的意思. 但在编程的语境中, 应该理解为: “我预计这个表达式必须成功, 否则就是严重的错误” 的意思. 但在编程的语境中, 应该理解为: “我预计这个表达式必须成功, 否则就是严重的错误”. 这是一种预设, 如果 expect 执行了, 就说明出现了严重的错误.

比如 Option::expect:

  • 如果 some_opt 存在, 则程序正常运行
  • 如果 some_opt 是 None, 则认为出现了严重错误, 打印报错信息并退出

同理 Result::expect:

  • 如果文件存在, 则正常运行
  • 如果文件不存在则打印信息并退出

unsafe 关键字

unsafe 能让编译器关闭一些检查, 从而允许一些可能会出现错误的写法. 这部分代码的正确性需要程序员来保证. 就算有错误, 也能编译通过.

在一些场景下必须使用 unsafe:

场景 为什么是 unsafe 你的责任
调用 C 函数 编译器不知道 C 代码有没有 UB (Undefined Behavior) 保证 C 函数的签名正确、参数有效、调用后 Rust 不变式成立
解引用裸指针 指针可能悬垂/错位/null 保证指针有效、对齐、指向已初始化的正确类型的数据
内联汇编（asm!） 汇编代码不受 Rust 语义控制 保证汇编不破坏内存 / 栈 / ABI
手动管理内存（alloc/dealloc） 可能 double-free、泄漏、use-after-free 保证每个分配恰好释放一次
绕过 UTF-8 检查 可能产生无效字符串 保证字节序列是有效 UTF-8
绕过边界检查 可能越界访问 保证索引在范围内
构造”不可变”数据的可变操作 可能违反别名规则导致 UB 保证修改方式不造成未定义行为
实现并发原语（Mutex、Atomic） 编译器不能自动验证线程安全 保证内存序正确、没有数据竞争

Fat Pointer

Fat Pointer (胖指针) 区别于普通 thin pointer:

  • Thin Pointer 只包含一个内存地址
  • Fat Pointer 除了包含内存地址, 还额外携带了一份元数据

之所以称为 “Fat”, 是因为在 64 位系统上, 普通指针占 8 字节, 而胖指针占 16 字节 (8+8), 占用的空间更大.

Fat Pointer 主要用来解决 DST (Dynamically Sized Type, 动态大小类型) 在编译期大小不确定的问题, 比如 [i32] 切片, 从类型上不知道大小, 编译器就没办法在栈上给它们分配空间.

DST 的大小实际上是知道的, 只是无法从类型上获取, 因此在编译期无法通过类型获取大小. 如果把这个具体的大小存到指针的部分空间里, 通过让指针的大小确定, 并且让 DST 的大小可以在运行时得到, 来解决这个问题.

Thin Pointer 与 Fat Pointer 的区分标准就是: 指向的类型在编译时大小是否确定, 如下面示例:

引用示例 指向的类型 类型是否 Sized 指针类型
&i32 i32 是 Thin Pointer
&[i32; 4] [i32; 4] 是 (固定长度数组) Thin Pointer
&[i32] [i32] 否 (切片) Fat Pointer
&str str 否 (字符串切片) Fat Pointer
&dyn MyTrait dyn MyTrait 否 (特征对象) Fat Pointer

Ord 和 PartialOrd

Ordering (排序), 指一组元素之间的大小关系或顺序关系.

Total Ordering (完全排序), 指对于集合中的任意两个元素 $a$ 和 $b$, 一定能确定它们之间的关系, 并且只有以下三种情况之一成立:

  1. $a < b$, a 小于 b
  2. $a == b$, a 等于 b
  3. $a > b$, a 大于 b

FFI 接口

FFI, Foreign Function Interface, 外部函数接口, 允许一种编程语言 (如 Rust) 调用另一种语言 (如 C) 编写的函数.

Rust FFI 可以用来:

  • 调用 C/C++ 等语言的库函数
  • 暴露 Rust 函数供其他语言调用

FFI 的核心是利用 C 语言的 ABI (Application Binary Interface), 因为其最通用和稳定, 几乎所有语言都支持.

裸指针不会像引用 (&T/&mut T) 那样受到 Rust 所有权与借用规则的限制, 可以绕过编译器的安全检查, 因此需要在 unsafe 块中解引用或操作.

Rust 为 *const T/*mut T 提供的常用方法有:

  1. read()/read_volatile(): 从裸指针指向的内存地址读取一个 T 类型的值

(read_volatile() 告诉编译器, 不要优化这个读取操作, 即使没有用到这个值, 也要从内存读取)

  1. write()/write_volatile(): 往裸指针指向的地址写入一个 T 类型的值

  2. as_ref()/as_mut(): 将裸指针尝试转换为引用 (&T/&mut T)

  1. offset(): 对裸指针进行指针算术 (加偏移量), 返回一个新的裸指针, 指向当前地址偏移 n * size_of::<T>() 字节的位置
  1. is_null(): 检查裸指针是否是 null

Turbofish 是 Rust 一开始就有的语法, 这个名字是 Rust 社区取的昵称: ::<Type> 这个语法长得有点像一条小鱼 (< >像鱼身子, :: 像鱼鳍或眼睛), 而且它让编译器 “加速” (turbo) 知道你想用哪种类型, 因此戏称为 Turbofish (涡轮鱼).

获取 Iterator 的方法

Rust 标准库实现的 collections (如 Vec<T>, &[T], HashMap 等) 都能转换为 iterator, 用于遍历.

常见的获取迭代器的方法有 3 种:

  • iter(), 调用对象是 &T, 返回的迭代器类型 Iter<'_, T>, 此时元素类型都是 &T (引用), 无法修改
  • iter_mut(), 调用对象是 &mut T, 返回的迭代器类型 IterMut<'_, T>, 此时元素类型都是 &mut T (引用), 可以修改元素
  • into_iter(), 调用对象是 T, 返回的迭代器类型 IntoIter<T>, 此时元素类型都是 T, 会获取元素所有权
