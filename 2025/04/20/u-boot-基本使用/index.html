介绍

U-Boot, Universal Bootloader, 是一个开源的跨平台 Bootloader, 主要用于嵌入式系统.

其主要任务是在操作系统启动前, 完成硬件初始化, 加载内核和根文件系统.

编译

U-Boot 采用与 Linux 内核相同的 Kconfig/Kbuild 系统, 所有功能开关最终体现在 configs/xxx_defconfig, .config, include/generated/autoconf.h 中. 头文件中会用 #ifdef CONFIG_XXX 这样的条件编译来控制.

BIOS, 引导扇区与引导程序的关系

  • BIOS, 是固件程序, 负责开机自检(POST), 硬件初始化, 并加载引导程序
  • 引导扇区, 是磁盘的第一个扇区 (512 bytes), 存储引导程序和分区表
  • 引导程序, 一个程序, 负责加载操作系统的核心文件

由于 u-boot 程序通常大于 512 bytes, 因此, 在引导扇区中先存储微型程序, 称 SPL. Secondary Program Loader, 其负责加载 U-Boot 主程序到内存. u-boot 主程序存储在后续扇区或特定分区.

U-Boot 环境命令使用

mmc

MMC (MultiMediaCard), 最初是一种可插拔的闪存卡标准 (类似 SD 的前身), 后来演生成

  • eMMC (embedded MMC, 焊在板子上的 Flash, 手机/开发板几乎都是这个)
  • SD/SDIO, SD 卡实际上是在 MMC 协议基础上扩展而言

MMC device, 就是 MMC/SD/eMMC 设备的统称.

part

用来查看设备的分区信息:

  • <interface> 指存储接口的类型, 比如 mmc, sata, usb, nvme
  • <dev> 是设备编号 (从 0 开始)
  • [partnim], 指定查看某个分区详情 (可选)

比如:

  • mmc 0 通常是 SD/microSD
  • mmc 1 通常对应板载 eMMC

printenv

这里说明下几个比较重要的变量:

  • bootdelay=1, 表明 u-boot 启动后 1 秒自动执行 bootcmd
  • bootcmd=run sdboot 是 u-boot 启动后自动运行的命令, run 是 u-boot 命令, 作用是执行一个环境变量里的多条命令, sdboot 就是一个环境变量名

这里说明下 sdboot 包裹的命令:

  • setenv bootargs, 设置环境变量 bootargs, 作为内核命令行参数. 之后的全部内容就是变量的值
  • ${xxx} 这里的变量有的是普通环境变量, 有的是从源码编译进来的辅助变量
  • ;\ 分两部分, ; 分隔命令, \ 是续行符
  • echo 用于打印信息, 后面不需要加引号, 都是会打印的字符
  • && 含义与 Shell 中一致, 前一个命令执行成功后运行后一条指令
  • 同 Shell, ; 用于分隔, if ... then ... fi 是控制块. $? 表示上一条命令的返回值
  • bootm 是启动 uImage/FIT Image 的命令
  • ${uImage_addr} 是内核镜像在内存中的地址
  • #config-xxx 是 FIT Image 中的一个配置节点

DM

DM, U-Boot Driver Model, 是 U-Boot 自己的设备-驱动框架, 跟 Linux 内核的 device/driver 模型是同一个思想, 在不使用 DM 时, 需要手动调用初始化函数, 传裸指针, 自己管理生命周期; 用 DM 框架能自动发现设备, 匹配驱动, 调用 probe(), 通过 ops vtable 操作等.
