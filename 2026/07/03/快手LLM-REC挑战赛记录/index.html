快手LLM-REC挑战赛记录

介绍

该 Blog 记录从快手 LLM-REC 挑战赛中学到的知识.

生成式推荐

传统的推荐系统通常是多级级联架构, 比如分为召回, 粗排, 精排三个阶段, 一个阶段的输出作为另一个阶段的输入.

一个问题是, 每个阶段的优化目标不一致, 需要为每个阶段训练不同结构, 不同规格的模型来处理数据. 这样的级联结构也难以吸收 AI 演进过程中的技术, 比如 Scaling law, RL 等.

OneRec 就是一种生成式推荐的框架, 核心思路是: 将召回和排序融合为单一阶段的 Encoder-Decoder 生成式架构, 直接端到端生成推荐结果.

LLaMA-Factory + transformers

transformers 是 HuggingFace 出品的一个核心模型库, 其本身不是一个训练框架, 而是提供了两个内容:

  • 模型定义层, 库中内置了所有主流架构的 Python 实现, 比如 Qwen2ForCausalLM, LlamaForCausalLM, GemmaForCausalLM 等, 这些 class 里面写好了 attention, FFN, layernorm, position encoding 等等模块的代码实现
  • 权重加载层, 提供 AutoModel.from_pretrained(path), 可以读取模型的 config.json 文件, 确定预训练模型使用的哪一个 class, 将其实例化后, 把 model.safetensors 的权重 tensor 填入对应参数

也就是说, transformers 负责一个现有的模型准备好 (模型代码, 权重加载). 而训练则交给 LLaMA-Factory, 其在 transformers 之上封装了完整的训练流程, 并且将配置导出到 YAML 中, 便于修改, 提供一行命令开始训练的便利性, 其完成的事情有:

  • 执行模型加载, 调用 AutoModel.from_pretrained(), 会自动读取 YAML 中的 model_name_or_path: /path
  • 设置训练方法, 用 LoRA 训练还是说全参训练, 通过 finetuning_type: lora / full 指定
  • 设置数据集, 读取 .jsonl, 然后通过 tokenize 拼成 batch, 最后 packing. 通过 dataset: biz_sft 指定
  • 设置模板, 比如按照 Qwen3 的 chat template 拼接 message. 通过 template: qwen3_nothink 指定
  • 启用显存优化, 比如替换 attention 实现 + fused 算子. 通过 flash_attn: fa2, enable_liger_kernel: true 指定
  • 设置训练配置, 配置 Trainer 的参数. 比如 learning_rate, epoches, batch_size 等

协同相似

“协同相似” 全称是 “协同过滤中的物品相似度 (Collaborative Item Similarity)”, 核心定义是: 两个物品被同一批用户共同消费过的程度衡量了它们的相似度.

比如有 10 个人和 10 部电影, 有两部电影这 10 个人都看过, 说明它们相似度高; 有 1 部电影没有和别的电影成对出现过, 那么它与其他电影的相似度都很低.

注意 “协同相似” 的计算是与内容本身无关的, 而是利用重合程度来判断. 两个物品的受众高度重合, 那么两个物品就很相似; 受众重合度低, 就不相似.

这里涉及到一个技术叫 “协同对齐”, 假设我们有两个物品的多模态 embedding, 它们从协同的角度来看, 应该是非常相似的, 但在实际的多模态 embedding 空间里可能非常远, 而 “对齐” 则是让这两个本该接近的物品在多模态 embedding 空间里拉近. “协同对齐”, 就是利用协同相似度来指导模型拉近两个物品在空间的位置.

模型参数的概念

每一个参数值的大小, 取决于它的精度, 这里以 1B (10亿, $10^9$) 参数量所占大小为例:

精度 每参数占用 1B 模型权重大小
FP32 4 Byte 4 GB
FP16/BF16 2 Byte 2 GB
INT8 1Byte 1 GB
INT4 0.5 Byte 0.5 GB

为什么总是以 B 为衡量单位, 可能的原因是 1GB 恰好是 1B bytes (K, M, G, 每个量级都是 $10^3$, 三个就是 $10^9$).

这样就能很快算出, 比如 0.8B FP16 的模型, 预计参数占用就是 $0.8 \times 2 = 1.6 GB$.

模型参数量估计

Attention

Attention 计算的参数:

$$
\displaylines
{
\begin{aligned}
W_Q, W_K, W_V \in R^{d_{model} \times d_{model}}
\end{aligned}
}
$$

参数量 $3 \cdot d^2_{model}$.

如果是 MultiHead Attention, 还需要一个 Linear 层混合多个头拼接后的结果. 多头拼接得到的维度是 seq x d_model (也就是输入的维度), 为了使混合后的维度不变, 因此 Linear 层该是 d_model x d_model, 参数量是 $d^2_{model}$.

FFN

FFN 的参数量就是输入输出维度相乘, 比如 Attention 之后的 FFN 的形状通常也是 d_model x d_model, 因此参数量还是 $d^2_{model}$.

LayerNorm

LayerNorm 的数学本质就是, 为每个特征维度学习一个 scale ($\gamma$) 和一个 shift ($\beta$), 因此参数量就是 $2 \times d_{model}$.

Embedding

Embedding 的参数量是词表大小乘以 embedding 维度, 比如 $W_{emb} \in R^{V \times d_{model}}}$, 那参数量就是 $V \cdot d_{model}$

Block

比如模型有 12 个 attention block, 那么就是 12 乘以 block 内的参数量.

Semantic ID

Semantic ID (SID, 语义 ID), 是一种用有意义的结构化编码来替代传统任意整数 ID 的物品标识方式 (这个很重要, 其用来标识物品, 找到对应物品). 它不是随机的数字序列, 而是从物品的语义内容 (文本描述, 图像特征, 用户交互模式等) 中提取出来的, 携带语义信息的离散编码.

比如:

  • 传统 ID: item_12345, 这个数字本身没有任何含义
  • Semantic ID: (3, 17, 42, 8), 这是一个层次化编码的元组, 是有语义的离散编码, 相似的物品会有相近的前缀, 比如统一类别的物品可能是 (3, 17, 42, 5) 或 (3, 17, 41, 9)

传统的 ID 可能是随机分配, 两个相邻的 ID (如 10001 和 10002) 可能代表完全无关的物品. 模型必须从零学习物品之间的所有关系, 没有任何先验信息的帮助. 对于一个新的物品, 模型如果看到的是传统 ID, 模型从来没见过, 就无法进行有效推荐; 而如果是 semantic ID, 由于有语义, 能够充分利用距离信息.

得到 Semantic ID

Google 在 TIGER 等论文中用的核心方法是, 先得到 Item Embedding, 然后用 RQ-VAE 逐层量化, 得到 $(c_1, c_2, c_3, c_4)$ 元组. 具体的步骤为:

  1. 用内容特征或协同过滤得到物品的稠密向量 e
  2. 第一层量化: 将 e 映射到第一个 codebook 中最近的向量, 得到离散码 $c_1$
  3. 计算残差: $r_1 = e - codebook_1[c_1]$
  4. 第二层量化: 将残差 $r_1$ 映射到第二个 codebook, 得到 $c_2$
  5. 重复上述过程, 残差会越来越小
  6. 最终得到 semantic ID: $(c_1, c_2, c_3, c_4)$, 其中 $c_1$ 代表粗粒度语义, $c_4$ 代表细粒度区分

比如一本书的 semantic ID 为 $(3, 17, 42, 8)$, 其中:

  • $c_1 = 3$, 表示 “科技类”
  • $c_2 = 17$, 表示 “计算机科学”
  • $c_3 = 42$, 表示 “机器学习”
  • $c_4 = 8$, 区别具体是哪一本 ML 教材

Embedding table 与 Codebook 的区别

两者的运行方向完全相反:

维度 Embedding Table Codebook
核心目的 学习物品/特征的表示 将连续向量离散化/量化
维度 行数 = 物品/特征数量 行数 = 离散码的数量（人为设定）
输入 离散索引（如 item_id=10001） 连续向量（如 CLIP embedding）
输出 该物品的稠密向量 离散编码（如 index=42）
方向 离散 → 稠密 稠密 → 离散

Embedding Table 的本质是一个 N x d 的可学习矩阵, 行数 N 是物品总数 (可能百万级); 列数 d 是 embedding 维度 (如 128):

  • 输入: 离散的整数索引
  • 输出: 连续的稠密向量
  • 问题: 当 N 很大时参数量巨大; 且新物品需要新增行, 重新训练
  • 保存的信息: 每行是一个物品的 “画像向量”, 编码了该物品在协同过滤和用户交互层面的信息

Codebook 的本质是一个 K x d 的可学习矩阵, 行数 K 是码本大小 (如 256, 1024, 远小于物品数); 列数 d (与输出向量维度相同):

  • 输入: 连续的稠密向量
  • 输出: 与该向量最近的原型向量的索引 (离散值), 或量化后的向量
  • 特点: K 固定且较小, 代表有限的 “模板” 集合
  • 保存的信息: 每一行是一个 “语义原型”, 是在整个向量空间中挑出的 K 个代表点, 类似于聚类中心. 相当于将向量空间划分为 K 个区域, 每个码是一个区域的中心

Pre-train

Pre-train (预训练) 是指用大规模数据 (通常是通用数据或无标签数据) 训练模型, 让模型学到通用的知识, 模式和表示能力.

之后就能在 pre-train model 的基础上, 用少量目标任务数据进行 fine-tuning. 好处是预训练的权重比随机初始化好得多, 收敛更快, 效果更好.

蒸馏构造 SFT

传统的 SFT 数据, 通常是人工编写 (问题, 答案) pair, 这种方式的成本极高, 且覆盖有限, 人可能写不出复杂的推理过程.

而蒸馏构造 SFT, 则是让一个强模型来自动生成 (问题, 推理过程, 答案), 把这些数据作为 SFT 数据, 然后训练另一个模型.

Knowledge Distillation (知识蒸馏) 的核心思想就是用大模型/强模型的输出作为软标签, 去训练小模型.

RL

对于一个具有指令遵循能力的模型, 让模型自发/探索地生成 CoT 轨迹, 之后通过 GRPO 等强化学习范式优化模型.

对于上面一句话, 非常重要的一点是 “对一个具有指令遵循能力的模型”. 意思是不能从一个预训练模型上进行 RL (Reinforcement Learning). 比如预训练模型收到 prompt “请推理：用户历史 [A,B,C] → 推荐?”, 他可能直接续写成一篇小说, 根本不按格式走. 此时 RL 探索的空间就是一篇混乱, 输出基本都是垃圾信息, 模型永远拿不到正向奖励信号, 模型不可能收敛.

SFT 模型知道 “推理的格式”, 它的输出结构是合理的, RL 只需要在此基础上优化推理的质量.

模型会根据 prompt 输出多个 CoT, 然后让一个强模型对 CoT 进行打分, 计算 reward.

Rollout candidates

Rollout candidates (展开候选项) 是指强化学习训练中, 模型对同一个输入 prompt 生成的多个完整输出序列. 这些输出是模型在当前策略下的 “尝试” 或 “推演”, RL 算法会对它们打分, 然后据此更新模型.

Rollout 一词在强化学习中的定义就是: 从当前状态出发, 遵循某个策略, 执行一系列动作, 直到到达终止状态, 记录整个 trajectory.
