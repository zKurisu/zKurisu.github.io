Linux-ioctl-系统调用

介绍

ioctl (input/output control) 是 Unix/Linux 下的一种系统调用, 用于执行一些设备特定的非标准操作.

这里的标准操作是指 write()/read() 模型, 其只能用于传输连续的数据流, 但是很多设备需要:

  • 配置参数: 设置波特率, 分辨率, 采样率等
  • 查询状态: 获取设备能力, 当前配置
  • 发送命令: 弹出光驱, 格式化磁盘, 启动视频流等

这些操作的本质是控制设备的行为, 而非以 “读/写数据” 为目的.

函数签名

  • fd, 打开的设备文件描述符
  • request, 命令码, 是一个编码了操作方向, 数据大小和设备类型的整数
  • ... 可选参数, 通常是一个指向结构体的指针 (用于传入传出配置数据)

命令码定义

命令码利用宏来生成, 比如在 <linux/ioctl.h> 或 <asm-generic/ioctl.h> 中定义的 4 个宏:

  • type 表示设备/驱动类型 (Magic Number), 是一个 8 位字符或数字, 用于标识 “这是哪个驱动”, 防止不同驱动的命令码相互干扰和冲突. 比如 V4L2 使用 V (ASCII 86). 在 ioctl-number.rst 中注册的常见类型示例如下:
  • nr (number) 表示命令编号, 是一个 0-255 的整数, 在同一个 type 内标识每个操作. 同样以 V4L2 为例:
  • dtype (data type, 数据类型) 表示传递给 ioctl 的结构体类型名, 便于宏用 sizeof(dtype) 来确定数据大小以及让内核判断用户传入的指针大小是否匹配

V4L2 示例

V4L2 (Video4Linux version 2), 是 Linux 内核中用于视频设备的驱动框架 (负责使用更底层的驱动, 提供驱动编写的模板) 和 API (向用户态程序暴露接口). 它提供了一套标准接口, 让用户空间程序直接与视频硬件交互.

核心能力有:

  • 格式协商: 查询/设置像素格式 (YUYV, MJPEG, NV12 等), 设置分辨率, 帧率等
  • 缓冲区管理: 支持 mmap 和 DMABUF 两种零拷贝方式
  • 流控制: VIDEOC_STREAMON 启动数据流, VIDEOC_STREAMOFF 关停数据流
  • 控制接口: 调节亮度, 对比度, 曝光等硬件参数

mmap

这里提到用 mmap 进行 “拷贝”, 因此也记录下 mmap 和 munmap 两个系统调用的作用.

mmap 是 Unix/Linux 系统中用于内存映射 (memory mapping) 的系统调用, 可用于文件映射, 共享内存等场景.

其函数签名如下:

  • void *addr 是期望映射的当前进程用户地址空间中的起始虚拟地址. 通常取 NULL, 让内核自己选择合适的地址
  • size_t len 是要映射的字节数, 由于内核以页为单位映射, 因此会向上取整到页大小的倍数
  • int prot (protect) 是内存保护权限, 控制映射区域的访问权限, 必须至少指定一种, 但需要注意, 如果是文件映射, 则权限不能超过文件本身的打开权限:
    • PROT_NONE, 不可访问
    • PROT_READ, 可读
    • PROT_WRITE, 可写
    • PROT_EXEC, 可执行
    • 可以组合比如 PROT_READ | PROT_WRITE
  • int flags 决定映射类型:
    • MAP_SHARED, 共享内存, 映射的内容对其他进程可见, 写操作会同步回文件
    • MAP_PRIVATE, 写时复制, 修改只对本进程可见
    • 前两个必须选择一个来指定, 下面的是辅助的标志
    • MAP_ANONYMOUS/MAP_ANON, 匿名映射, 不需要关联文件 (fildes = -1)
    • MAP_FIXED, 会强制使用 addr (比较危险)
    • MAP_NORESERVE, 不预留交换空间
    • MAP_LOCKED, 锁定内存 (类似 mlock)
  • int fildes (file descriptor), 指定映射的文件描述符:
  • off_t off (offset), 文件偏移量, 指定从文件的第 off 字节开始映射. 必须是页的整数倍大小, 通常用于映射大文件的某一段
  • void * 返回值. 会返回映射区虚拟地址的起始地址. 注意不要用 == NULL 来判断是否映射成功, 而是用:

用 read/write 时, 内核在地址空间中为 DMA 分配一个 buffer, 之后硬件 DMA 传输数据时会先写入到这个 buffer 内. 内核在收到用户指针和长度信息后, 会找到对应的物理页并将 buffer 内容拷贝过去.

而在用 mmap (memory map) 时, 内核会先找到 DMA 写入的物理页位置, 然后在用户地址空间中找到一片可用的虚拟地址, 建立映射关系到 DMA 写入的物理页上. 这个步骤没有任何拷贝, 只是 DMA 和用户态程序都公用了这块物理地址:

V4L2 驱动会在 Linux 内核注册一个 mmap 回调, 比如摄像头设备是 /dev/video0, 那么用户态程序在调用 mmap 并且 fd 绑定到 /dev/video0 时 (这里的 fd 不是说映射文件内容, 而是用来从设备文件取出对应的 buffer, 此时的 offset 也不是文件偏移, 而是一个 buffer 的唯一标识符), 就能调用这个回调得到正确映射的虚拟地址.

munmap (memory unmap) 则是将之前的映射关系解除, 本质上就是清除对应虚拟地址的页表项.

  1. VIDEOC_QUERYCAP 展开为 _IOR('V', 0, struct v4l2_capability)
  2. 宏编码出命令码：读写方向 2 / 数据大小 104 / 魔数 ‘V’ / 编号 0

  5. 驱动填充 struct v4l2_capability，copy 回用户空间

查询 V4L2 controls

Controls 是 V4L2 的一套参数读写机制, 用于调节摄像头/视频设备的可配置属性, 而不需要知道硬件寄存器的细节.

Controls 本质上是对硬件参数的抽象, 每个 control 对应一个可调整的参数, 用户提供 id (选择要修改哪个参数) 和 value (具体要调整的值), 驱动负责把值翻译成硬件操作.

Class 比如:

  • V4L2_CTRL_CLASS_USER = 0x00980000, 表示用户控制 (亮度, 对比度等)
  • V4L2_CTRL_CLASS_CAMERA = 0x009A000, 表示相机控制 (曝光, 白平衡等)

Class 加上 Offset 比如:

  • CLASS_USER + 0x900 就是 V4L2_CID_BRIGHTNESS = 0x00980900
  • CLASS_USER + 0x901 就是 V4L2_CID_CONTRAST = 0x00980901
