LLM-Finetuning-基础

B 站吴恩达课程

介绍

LLM Finetuning 是指在一个预训练好的通用大语言模型 (Pre-trained LLM) 的基础上, 使用特定的任务数据或领域数据继续训练模型, 使其在特定任务, 场景或领域中表现更好的过程中, 比如:

  • General Purpose 的 GPT-3 在 finetuning 后变成 Specialized 的 ChatGPT
  • General Purpose 的 GPT-4 在 finetuning 后变成 Specialized 的 Github Copilot

除了让 base model 学到 specific 领域的知识外, finetuning 还能帮助模型产生更一致的输出或行为, 并且减少幻觉 (hallucinations), 比如我想让模型在遇到特定 prompt 的时候输出自定义格式或风格的输出:

Finetuning 在 LLM 训练中的位置

Finetuning 通常位于 pre-training 之后. 在 Pre-training 过程中, model 的参数是从完全随机开始的. 此时的训练任务是 next token prediction. 这通常需要先从互联网上爬取大量无标签的数据, 清洗后让模型开始自监督学习. 在训练之后, 模型能够预测出给定单词的下一个可能的单词, 并且具备一定通识能力.

比如用 “The Pile” 数据集来做 pre-training (一个经过精心整理得到的高质量 pre-training 数据集, 其包含 22 个不同的数据集, 旨在为模型提供广泛的知识). 模型需要把这些数据全部过几遍, 而这个过程会消耗大量时间和算力资源.

在 finetuning 阶段, 则不需要太多的数据了, 此时更要求数据集的质量. Finetuning 的训练目标也是 next token prediction, 只不过此时的训练数据需要组织得更结构化, 从而让模型的输出更加一致.

Data Preparation

一个好的数据集通常是:

  • Diversity, 包含覆盖各种场景. 如果所有输入输出都差不多, 模型会尝试去记忆, 泛化差
  • Real, 通常比 LLM 生成的数据更好, LLM 生成的大多具有某种特定的模式
  • More, 通常是越多越好, 但在 finetuning 阶段, 其没有前两点那么重要

Data preparation 的步骤通常有:

  1. 收集 instruction-response pairs
  2. 拼接 pairs (添加 prompt template)
  3. 用 pad, truncate 来 tokenize
  4. 拆分为 train/test

Practical approach

对模型做 finetuning 可以考虑下面步骤:

  1. 搞清楚要做的 task
  2. 收集与 task 相关的 inputs/outputs 数据
  3. 没有足够数据的话用其他数据集生成
  4. 先微调一个小模型练练手 (400M ~ 1B)
  5. 调整用于训练模型的数据量, 观察用多少数据合适
  6. 用一些指标评估 finetuning 出的模型的好坏
  7. 收集更多数据来提升
  8. 增加 task 复杂性
  9. 提升模型容量来提升性能 (7B, 14B 等等)
