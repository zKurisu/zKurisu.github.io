USB Debugging

USB Debugging 就是指电脑通过 USB 连接手机后进行系统调试. 这通常需要借助 ADB (Android Debug Bridge) 工具, 其用于在 PC 和 Android 设备之间建立通信, 是 Android SDK Platform-Tools 的核心组件之一.

ADB 是 C/S 架构 (Client-Server Architecture), 由 3 个组件构成:

  • ADB Client, 终端输入 adb 命令后扮演的角色, 运行在 PC 上
  • ADB Server, 在 PC 后台运行的守护进程, 管理 Client 与 ADB Daemon 之间的通信, 监听本机的 TCP 5037 端口
  • ADB Daemon (adbd, 手机上), 运行在手机上的后台程序, 接收并执行来自电脑的命令

ADB Client 用 TCP 在本机 5037 端口与 ADB Server 通信, ADB Server 通过 USB/WiFi 与手机设备上的 ADB Daemon 通信.

在 HUAWEI Pura 70 HarmonyOS 版本 4.2.0 上, 需要在开发者模式中启用 USB 调试, 并且把 USB 配置替换为除 “仅充电” 以外的选项 (这里选的是 RNDIS):

Android 文件系统

Android 设备的文件系统通常不是一整块, 而是由多个独立分区 (Partition) 组成, 每个分区有不同的挂载点 (Mount Point) 和权限, 比如:

/ 的默认挂载参数是 ro,nosuid,nodev,noexec, 因此默认是只读的. 如果 root 用户想写入, 需要 mount -o remount,rw / 来以读写方式重新挂载.

/sdcard/ 是用户存储空间, ADB shell 用户对其有完整的读写权限, 因为:

  1. /sdcard/ 用的是支持写的文件系统 (sdcardfs/FUSE)
  2. shell 用户在 sdcardfs 的权限规则里被赋予了写权限
  3. 其设计目的就是用户文件存放区, 必须可写

GMS 和 MicroG

GMS (Google Mobile Services, 谷歌移动服务), 是一套由 Google 开发的预装在 Android 设备上的专有软件包和服务集合, 是闭源的商业软件.

GMS 不是一个单一应用, 而是多个组件构成:

  • Google Play Service, com.google.android.gms, 是 GMS 的核心 runtime, 包含所有 Google API 的实现
  • Google Play Store, com.android.vending, 应用商店
  • Google Services Framework, com.google.android.gsf, 底层框架, 含账号认证和设备注册
  • Google Play Protect, 集成在 Play Store 中, 安全扫描, 检测恶意应用
  • Google Location Services, 集成在 Play Services 中, 高精度定位 (融合 GPS, WiFi, 基站)

当一个 App 调用 Google 服务时, 它实际上是在调用设备上已安装的 Google Play Services 提供的 API. 如果没有 GMS, 调用则会失败.

MicroG 则是一个开源软件, 其使用相同的包名和 API 伪装成 GMS.

APKMirror

APKMirror 是一个第三方在线仓库, 专门托管 Android 应用安装包的 APK (Android Package Kit) 文件. 用户可以直接从网站下载 APK 文件, 然后手动安装到 Android 设备上.

.apkm 文件需要用 APKMirrorInstaller 来安装.

MT 管理器

MT Manager 是 Android 上最强大的文件管理器之一, 其集成了 APK editor, test editor, hex editor, decompiler, foot file explorer 等功能.
