研究生开源操作系统大赛记录

介绍

该 Blog 记录在参加研究生开源操作系统大赛学到的一些知识点.

rootfs

因为编译 StarryOS 时, 需要先运行 make rootfs, 因此调研下这个概念.

rootfs 正如其名, Root FileSystem, 是 Linux 内核启动过程中挂载的第一个文件系统, 它是所有其他文件系统的根.

但 rootfs 和寻常我们理解的文件系统有所不同, 它是一个由内核在启动阶段自动创建的存在于内存中的临时文件系统 (类型是 tmpfs), 而非磁盘上. 特点就是它不依赖任何块设备/磁盘驱动, 并且内容为空. 没错, 它是空的.

尽管 rootfs 为空, 但它确实作为了文件系统的根节点了, 其下可以放置文件了.

这里从 Linux 内核启动再理一边. Linux 内核在编译时会链接一个 initramfs (或者是一个独立的 initramfs 文件), 其本质是一个 cpio 压缩包. 内核在启动后, 会进行下面操作:

  1. 创建空的 rootfs (tmpfs)
  2. 把 initramfs 的内容解压到 rootfs 中
  3. 此时 rootfs (/) 之下, 就有了 /init, /bin/, /lib/ 等基本内容

之后内核会执行 /init 文件 (一个 shell 脚本或编译好的二进制), 其会进行:

之后内核会用 switch_root 或 pivot_root (函数), 把根从 initramfs 的 tmpfs 切换到 /mnt/realroot 上.

switch_root 干了 3 件事情:

  1. 把 /mnt/realroot 移动为 /
  2. 清空旧的 initramfs 内容 (释放内存)
  3. 执行新根下的 /sbin/init (系统真正的 init 进程)

之后系统就开始正常运行了.

musl libc

musl 是一个为 Linux 设计的轻量级, 标准兼容的 C 标准库. 其设计哲学是: 正确性优先, 简洁, 高效. 正因如此, 它对静态链接非常友好, 编译后体积小.

这里与常见的 glibc 对比:

二进制大小 动态库 ~2 MB 动态库 ~0.6 MB，静态链接后仍很小
线程实现 NPTL (1:1 线程模型)，复杂 轻量级 1:1 线程，代码极简
malloc ptmalloc，复杂，fork 可继承 mallocng (2019 年后)，简单高效
DNS 解析 libnss (NSS 框架)，支持插件 内置实现，无外部依赖，无 nscd
locale 完整 locale 支持，数据文件数百 MB 精简 locale，数据内嵌
数学库 多年累计，悠久但部分代码陈旧 正确舍入优先，现代算法

许可证 LGPL MIT

ONNX

ONNX (Open Neural Network Exchange) 是一个深度学习模型的中间表示 (Intermediate Representation, IR), 由微软和 Facebook 于 2017 年联合发布, 目的是解决 “每个框架训练出来的模型, 如何在其他框架/运行时中使用” 的问题.

不同框架训练的模型格式不同, 只能在自己框架下进行推理.

而 ONNX 要做的事, 就是:

  • PyTorch $\rightarrow$ model.pt $\rightarrow$ [export] $\rightarrow$ model.onnx $\rightarrow$ [import] $\rightarrow$ 任意支持 ONNX 的运行时
  • TensorFlow $\rightarrow$ model.pb $\rightarrow$ [export] $\rightarrow$ model.onnx $\rightarrow$ [import] $\rightarrow$ 任意支持 ONNX 的运行时

[export] (导出), 就是模型转换的过程, 而 [import] (导入) 就是模型加载的过程.

tract crate

tract crate 是 Sonos 公司开源的一个 Rust 推理引擎, 全称是 Tiny, Runnable, And Connective. 它可以在纯 Rust 环境中加载 ONNX 和 TensorFlow 模型并执行推理.

tract 的设计理念并不是追求极致的推理速度, 而是追求嵌入便利性和部署简单. 其后端是 CPU (意思是在 CPU 上推理), 也可选 WASM. 由纯 Rust 编写, 因此几乎零系统依赖.

BootROM

BootROM (Boot Read-Only Memory) 是嵌入式/计算机体系结构中 CPU 上电后执行的第一段代码所在的只读寄存器, 也叫 ROM bootloader 或 Stage 1 Bootloader 这是芯片出厂时就烧死在 ROM 里的代码, 不可修改.

BootROM 负责把真正的 Bootloader 加载到内存并跳转运行, 它是 “引导程序的第0步”, 早于 BIOS/UEFI/SPL/U-Boot.

FIP

FIP (Firmware Image Package), 是一种固件的打包格式 (由 ARM Trusted Firmware 定义), 用于将多个固件镜像打包成一个文件. 比如将 OpenSBI 和 U-Boot 打包成 fip.bin, 作为 Boot Loader Stage 2 来使用.

FIP 的原始概念是: ARM 启动有多个安全级别 (EL3, EL2, EL1 等), 每级需要不同的固件. FIP 将这些固件打成一个包, BootROM 或上一级固件可以从包中提取自己需要的部分. 这里借用了这个术语, 只包含了 OpenSBI 和 U-Boot 两部分.

OpenSBI (Open Source Supervisor Binary Interface), 是 RISC-V 的标准 SBI 固件, 为操作系统提供底层服务 (定时器, IPI, 电源管理等).

U-Boot (Das Universal Bootloader), 是一个开源通用的引导程序, 支持从 SD 卡/NAND/NFS 等加载内核.

从这两个软件的作用也可以看出:

  • OpenSBI (SBI Runtime) 会一直驻留内存 (运行在 M Mode), 内核会持续调用它, 设备树中常用 /reserved-memory 来标记:

  • U-Boot 会在启动完成后退出执行, 通常被覆盖或丢弃

BootROM 解析 FIP 的流程如下:

  1. 读取 fip.bin
  2. 解析 FIP 头
  3. 把 OpenSBI 放到 RAM 的一个保留区域
  4. 把 U-Boot 放到 DRAM 可执行地址
  5. 跳转到 U-Boot
  6. U-Boot 加载内核并跳转

FIT

FIT (Flattened Image Tree), 是 U-Boot 的一种内核打包格式, 将内核镜像, 设备树, ramdisk 等打包到一个二进制文件中. 注意区分前面的 FIP (Firmware Image Package), 其用来打包 Stage 2 Bootloader 和 SBI.

这里又涉及到了几个格式和术语:

  • ITS (Image Tree Source), 是 FIT 镜像的文本描述文件 (类似源文件, 描述包含哪些组件, 如何加载, 加载到哪里等), U-Boot 的 mkimage 工具将其编译为 FIT
  • DTS (Device Tree Source), 设备树的文本源代码, 编译后得到 .dtb
  • DTB/FDT (Device Tree Blob/Flattened Device Tree), 一个描述硬件拓扑的数据结构, 由内核在启动时解析

USB Controller 是 SoC 内部的一个外设模块, 管理从 Type-A/Type-C/Micro-USB 等接口传来的数据, 提供设备枚举等功能.

USB 是主从 (Master-Slave) 总线:

  • Host (主机), 负责发起通信事务 (主导通信), 如 PC, 路由器
  • Device (外设), 被动响应 (接收数据等), 如键盘, U 盘, 开发板 Gadget

USB 不允许两个 Host 直接相连.

USB Controller 工作在 Host Mode 时, 会负责检测插入, 复位设备, 读描述符, 分配地址, 调度数据传输等.

工作在 Device Mode 时, 不主动发数据, 会响应 Host 的 Token, 向 Host 汇报描述符等.

Loop Device 的作用
