Kaggle-入门指南

介绍

Kaggle 是全球最大的数据科学与机器学习竞赛平台, 成立于 2010 年, 在 2017 年被 Google 收购. 其提供有很多免费课程可以学习, 而且每周有免费 GPU/TPU 额度, 可以配套其集成的数据集, 模型进行实战练习.

企业/机构会在 kaggle 上发布真实的预测问题作为竞赛, 参赛者通过提交预测结果取得分数和排名.

由于 “Kaggle” 和英文单词 “gaggle” (一群鹅) 长得很像, 所以 Kaggle 的默认头像/符号是一只鹅.

Kaggle Notebook

Kaggle notebook (以前称 kaggle kernel) 本质上是运行在浏览器里的 Jupyter notebook, 由 kaggle 平台免费提供. 配套有 GPU/TPU 资源可以用于模型训练.

如果别人有公开一个比赛的 notebook, 你也可以直接 fork 过来学习或者复现实验.

通常 notebook 所处环境是待机的状态, 在浏览器上可以查看 notebook 的内容. 如果运行了 notebook, 就会启动云端服务器:

  • 提供 4 核 CPU, 30GB 内存, 单次 Session 时间上限是 12 小时, 重启 session 能重置. 每周额度不限
  • 磁盘显示可用 57GB, 其中持久化磁盘目录是 /kaggle/working 只有约 20GB, 其余空间用来存放临时数据, 在 session 结束后会清空. 另外 /kaggle/input 是只读的, 用于存放挂载的数据集

  • GPU 可选 Tesla P100 16GB 或者两张 T4 (共 32GB), 每周额度 30 小时
  • TPU 可选 TPU v3-8, 每周额度 20 小时

Kaggle Environments

Kaggle Environments 分两种:

  • kaggle-environments Python 包, 其用作模拟类比赛的游戏环境库
  • gcr.io/kaggle-images/python:v163 Docker 镜像, 是 Kaggle 上 Notebook 运行的环境

如果只是要部署比赛环境, 通常装 pip 包即可. 如果是要自己搭建 Kaggle 那样的评测基础设施 (镜像中带有一些评测脚本), 比如多容器, agent 隔离评测等, 此时采用得到这个镜像.

kaggle-environments

这个库是官方微模拟/强化学习类比赛提供的库, 用来跑 episode 和评测 agent. 其内置了一堆现成的游戏环境, 比如 tictactoe, connectx 等等. 核心是 Gym 风格, 且 agent 被抽象为一个函数.

后面会用 connectx 这个比赛来说明 kaggle-environments 的使用.

示例:

  • make 用来创建一个强化学习环境, 第一个参数用于指定一个预先准备好的环境
  • env.run([]) 指定一个列表开始游戏, 但 connectx 要求列表长度为 2
  • env.render(mode="") 渲染游戏过程, 可选 mode 有:
    • ipython, 把 html 直接渲染到 Notebook 输出, 便于在 jupyter/kaggle notebook 里交互观看
    • ansi, ASCII 文本, 在终端里看棋盘 (实测在 jupyter 里面效果不佳)
    • human, 同 ansi, 打印到 stdout (在 jupyter 里没看到输出)
    • html, HTML 字符串 (在浏览器里面也很难看), 用于在浏览器打开查看
    • json, JSON 字符串 (env.toJSON()), 便于存盘, 调试
  • random 会从所有 valid moves 中均匀选取一个动作来执行, 对于 connectx 而言, 当某一个 column 有空闲的时候都算 valid
  • my_agent 是自定义的 agent, 本质就是一个 Python 函数, 接受 obs 和 config 两个参数, 返回值是 0-6 之间的整数 (向哪一个 column 扔一个 dice). 如果返回了一个 invalid move, 则会直接判负
  • obs 在这里包含两部分信息:
    • obs.board, 一个 Python list, 注意不是二维数组, 是一个平铺的一维数组, 先是棋盘的第一行, 接着是第二行, 值为 0 表示空, 值为 1 表示 player 1 的 discs, 值为 2 表示 player 2 的 discs
    • obs.mark, 表明这个回合中, 你是哪个玩家 (1 号还是 2 号)
  • config 包含 3 部分信息:
    • config.columns, 表示一共有多少个 columns (Connect Four 中是 7)
    • config.rows, 表示一共有多少个 rows (Connect Four 中是 6)
    • config.inarow, 指定要多少个连成一行才算获胜 (Connect Four 中是 4)

    • action, 这一步下在哪一列
    • reward, 这步的及时奖励 (通常是 None, 终局才有值)

Kaggle Competition

奖牌规则

对于大型比赛 (1000+ 队伍报名), 获奖规则是:

  • Gold, 前 10 + 0.2% (5000 只队伍参加大约 20 枚)
  • Silver, 前 5% (5000 只队伍参加大约 250 枚)
  • Bronze, 前 10% (5000 只队伍参加大约 500 枚)

等级排行:

  • Contributor: 完成基本活跃 (提交 1 次, 跑一个 Notebook, 发 1 条评论)
  • Expert: 2 枚铜牌
  • Master: 1 金 + 2 银
  • GrandMaster: 5 金 (含至少 1 枚个人/队长金牌)

奖金规则由主办方定.

learntools

learntools 是为 Kaggle Learn 设计的 “练习检查/反馈工具” 包, 比如导入某个课程的练习, 检查自己的结果是否正确, 打印提示信息等.

在 “Intro to Game AI and Reinforcement Learning” 课程练习里一开始就能看到:

这里要先解释下什么是 IPython: 它是 Jupyter Notebook 的 kernel, 即真正执行代码的那个 Python 进程. 它和 python script.py 的本质区别是, IPython 有一个跨 cell 持久存在的命名空间:

  • 普通脚本跑完就结束了
  • Notebook 里你在第 1 个 cell 定义的东西, 第 20 个 cell 还能用, 因为 IPython 一直持有那个 dict

而 binder.bind(globals()) 就是把 IPython 持有的命名空间 user_ns 的引用绑定给 binder.

from learntools.game_ai.ex1 import * 会运行 game_ai.ex1 这个文件, 并把所有名称拷入当前命名空间. 在这里主要有 q_1..q_5

之所以要把 user_ns 传递给 learntools, 主要是为了带来下面好处:

它会自动通过调用 user_ns 的 keys() 方法, 找到你在 Notebook 中定义的对应变量, 然后查看运行是否正确.

如果不用上述方式, 比如手动向 check 传入要接受判断的变量, 会有一些麻烦之处:

  • 每个 exercise 的检查变量不同, 意味着传递给 check 的参数不同, 如果少传或顺序出错, 都会出问题
  • 每当 exercise 作者改变了 check 的参数, 所有 learner 都需要更新自己的 Notebook 来适配

binder 对象

binder 定义在 lt/learntools-master/learntools/core/globals_binder.py 中, 本身的 class 定义也非常简短:

  • self.bound 用来判断是否重复绑定 (bind 的完成时)
  • self.g 用来存储 Notebook 中的那个全局命名空间 dict
  • id(obj) 返回对象的身份编号, 也就是 CPython 里的内存地址. 在对象存活期间, 它唯一且不变. a is b 本质上就是 id(a) == id(b)
  • ReadOnlyGlobals 就是包裹成一个只读的字典:
    • obj[key] 能映射到 __getitem__ 协议
    • key in obj 能映射到 __contains__ 协议

包的组成

core 是所有课程都共用的引擎包, 而 game_ai, python, pandas, sql 这些都是课程子包, 都是重复同一种结构定义教程.

Problem 基类

Problem 类是一个 Abstract Base Class (抽象基类), 意思就是不能实例化, 只能用作模板让其他 class 继承:

  • _solution, 类属性, 设置答案的默认值. 通常子类需要覆盖它
  • _counts_for_points = True, 类属性, 表明该 problem 是否计入总分分母
  • _bonus, 类属性, 给加分题使用, 不计入分母, 但答对能加分
  • solution, property, 只读暴露 _solution
  • hints, property, 把 _hint/_hints 统一成 list
  • _correct_message, property, 控制是否在答对时把答案一起显示
  • check, abstractmethod, 继承的子类必须实现该方法
  • check_whether_attempted, 普通方法, 一个默认空实现的可选钩子
