Binary-indexed-tree

B 站参考视频

介绍

Binary Indexed Tree (BIT, 又称 Fenwick 树, 树状数组) 是一种比较巧妙的数据结构, 能够以 $O(logn)$ 做元素修改和前缀和查询.

之所以设计这么个数据结构, 想象下面场景, 假设我们有一个长度为 n 的数组 a, 需要反复做两类操作:

  1. 修改: a[i] += delta
  2. 查询: 求 a[l] + a[l+1] + ... + a[r-1] (即区间 [l,r))

上面的两个操作只是示例, 比如修改也可以是 a[i] = new_val, 查询也可以是 max(a[l..r]) 等等. 核心思路是利用二进制拆分进行前缀信息维护.

如果是普通数组的形式:

  • 修改是 $O(1)$
  • 查询是 $O(n)$ 需要把区间扫一遍

如果是直接存储前缀和 pre[i] = a[0] + ... + a[i-1]:

  • 查询变成 pre[r] - pre[l], $O(1)$
  • 但只要 a[i] 变更, pre[i+1], pre[i+2], …, pre[n] 全部都得改, 修改退化到 $O(n)$

为此, 就需要有一种折中的办法, 虽然修改和查询都不能到 $O(1)$, 但都能优化到 $O(logn)$, 不至于是 $O(n)$.

Update

修改位置 x 的元素, 那么所有包括 x 的区间和也会发生变化, 那么 tmp 中哪些包含了位置 x 呢:

  • 首先以 x 为端点的 tmp[x] 肯定要更新
  • 以 i 为端点且 i < x 的 tmp[i] 不用更新, 毕竟 tmp[i] 都没有包含 x, 它改变了也没影响
  • 那么 i > x 就有可能更新, 前提是 i - lowbit(i) 需要小于 x

针对上面的第三点, i - lowbit(i) < x, 意味着 tmp[i] 的区间需要大, 而我们知道区间长度是 i 二进制表示的最低位 1, 比如 100100 如果让它进位为 101000, 那么 lowbit 就会变大, 而 i + lowbit(i) 就能实现这个进位 (100100 + 000100).

比如 k = x + lowbit(x), 由于进位, 一定就有 lowbit(k) >= 2 * lowbit(x) (比如 lowbit(0b1001) = 2^1, 进位后 lowbit(0b1010) = 2^2), 那么就有 k - lowbit(k) = x + lowbit(x) - lowbit(k) <= x - lowbit(x) < x, 既然左区间小于 x, 说明就是包含了 x. 因此 tmp(x + lowbit(x)) 也需要更新. 直到右边界更新到超出 n.

这里可能会有一个疑惑, 直接改 x + lowbit(x), 那 x + 1, x + 2 这些中间值需要改吗? 答案是不需要. 假设我们加上了一个比 lowbit(x) 小的数 $\Delta$ (即 $0 < \Delta < lowbit(x)$), 令 $k = x + \Delta$, 根据二进制性质, 因为 $\Delta$ 太小, 无法让 x 的低位 1 发生进位, 就会有:

  • k 的右边界挪到了 $x + \Delta$
  • lowbit(k) 最多只能等于 $lowbit(\Delta)$
  • 左边界为 $k - lowbit(k) \ge (x + \Delta) - \Delta = x$, 即左边界最小也就是 x, 但是是开区间所以不包括

实现示例

抽象

Binary Indexed Tree 本质上是一个基于二进制拆分的 “动态前缀信息维护器”, 因此肯定不限于之前示例的累加和查询区间和操作.

设计 BIT 时, 核心是抽象出 index (索引), value (值), update & query (操作语义):

  • Index (下标), 通常不是原数组的简单序号, 而是某种被排序, 离散化或状态化后的指标 (比如数值大小, 时间戳, 坐标等, 通常需要反问: 我要按什么做前缀统计)
  • Value (数值), 树状数组中保存的统计量 (比如频次/计数, 最大值, 概率, 某种权重的累加和等, 需要反问: 我要在这个 index 范围内统计什么)
  • Update & Query, update 指在产生一个新的数据点时, 如何在某个 index 上增加/覆盖 Value; 而 query 指查询 index 在 [1, k] 范围内 (即前缀) 的 value 合并结果

一个经典的例子是求 “无序数组中的逆序对数量”, 比如: 给定一个无序数组 [5, 2, 6, 1], 求逆序对 (即满足 i < j 且 A[i] > A[j] 的下标对数).

如果我们从左到右遍历数组, 对于当前遍历到的数 v, 我们需要知道在它左边已经出现的数里, 有多少个数比 v 大 (比如 1, 它左边有 3 个数比它大, 那么至少就有 3 个逆序对).

一个重要的思考是: 原数组的下标顺序关系不重要, 也不需要存储. 因为我们会顺序遍历原数组来构建 BIT, 数据点的出现已经是顺序的了, 此时的统计信息, 就一定是前缀的统计量.

比如这个问题可以这样设计:

  • Index 是数值本身的大小
  • Value 是该数值出现的频次
  • Update(v, 1) 表示该数值出现了一次, 在该位置计数 +1
  • Query(v) 查询当前已遍历的数中, 数值 $\le v$ 的数字一共有多少个 (前缀频次和)

求最长递增子序列长度的朴素动态规划思路是: 令 dp[i] 表示以第 i 个数 A[i] 结尾的最长递增子序列长度. 为了求 dp[i], 就需要在前 i-1 个数里面, 找到一个满足 A[j] < A[i] 的位置 j, 并取出最大的 dp[j]. 伪代码是:

内层循环会把前面所有的 j 都线性扫描一遍, 这导致 $O(n)$ 的时间复杂度. 因为这里有两个限制条件:

  1. 位置限制: j < i (j 必须在当前数的前面出现)
  2. 数值限制: A[j] < A[i] (j 位置的数值必须比当前数值小)

如果我们是从左往右遍历数组 A 的, 并且每次都会从元素中取出统计信息存入某个数据结构, 那么 j < i 天然就是满足的, 因为遍历到当前数时, 前面的数的信息已经处理保存了.

这里有很明显的要使用 “前缀的统计信息” 这个标志, 并且要一个一个追加, 说明可以用 BIT 来优化.

因此只剩下 A[j] < A[i] 这个条件, 数据结构中我们需要存储的统计信息就是 dp 值 (最长递增子序列长度), 那要如何存才能在前缀中快速找到 “所有数值比 A[i] 小的那些 dp 值的最大值” 呢?

假设直接用 “数组下标” 作为 index, 此时数据结构中存的是 [dp[1], dp[2], dp[3], ...], 当你处理到 A[i] = 5 时, 还是需要从数据结构中顺序遍历, 因为此时的 index 不具备判断信息.

要让 index 具有数值顺序信息, 那么就用 “数值本身” 作为 index (这里的一个启示是, index 的设计需要考虑判断条件的顺序关系).

此时 tree[v] 表示在已经处理的数中, 数值为 v 的那个数对应的最大 DP 值. .

此时 “比当前数值 A[i] 小这个条件”, 在 index 上就变成了: 寻找 Index 落在 [1, A[i]-1] 范围内的最大值.

需要注意, 如果一个数值是 10000, 是不是要创建一个大小为 10000 的数组呢? 肯定不能这样做. 我们可以发现 LIS 根本不在意具体数值大小, 而只是关注其相对顺序 (比如 [100, 200, 500] 和 [1, 2, 3] 在这里是完全等价的). 因此可以做一次离散化, 把真实的数值映射为它们的排名 (rank).
