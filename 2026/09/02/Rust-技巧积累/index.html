BTreeMap

BTreeMap 是 Rust 标准库 std::collections::BTreeMap 提供的一个基于 B-树 (B-Tree) 实现的键值对容器.

它与 HashMap 的最大不同在于: BTreeMap 中的键 (key) 永远保持有序状态. 因此 key 需要实现 Ord (全序).

BTreeMap 的插入/删除/查找都是 $O(logN)$ 的时间复杂度. 范围查询时效率极高, 还能 $O(logN)$ 快速获取最大/最小值.

C++ 的 std::map 底层采用红黑树, 而 Rust 选择 B-Tree. 因为 B-Tree 的节点会连续存储多个元素, 对 CPU 缓存 (Cache Line) 非常友好, 在现代计算机硬件上的实际运行性能通常优于红黑树.

通常在需要顺序遍历键值对, 区间查询, 或频繁找最小值最大值时考虑使用 BTreeMap, 纯粹单点最增删改查时用 HashMap.

整数转换为引用

Rust 中禁止直接 usize as &T 或 usize as &mut T 这种语法, 因为引用 (Reference) 在 Rust 中是绝对安全的保障 (生命周期, 非空指针, 内存对齐, 别名规则), 语言不允许通过一个简单的 as 凭空创造出一个引用.

转换需要严格分为两步:

  • 可以将 usize 转换为裸指针. 而裸指针仅仅是一个 “内存地址的标记”, 编译器不会假设这个地址是有效的, 对齐的或是非空的
  • 裸指针转换为引用需要借助 unsafe 来提权, 是编程者向编译器做出担保:
    • 这个地址是非空的
    • 这个地址指向的内存是经过正确对齐的
    • 这个地址确实存放了一个有效的 T 类型对象

HashSet/HashMap 内元素的随机访问

需要注意, 虽然指定 key 访问 HashSet/HashMap 内的元素的时间复杂度是 $O(1)$, 但是想要随机访问却是 $O(N)$.

HashSet 和 HashMap 的底层是一个哈希桶数组 (Bucket Array), 假设开辟了 16 个桶空间, 当你存入 3 个元素时, 还会有 13 个空洞. 如果用 0~15 随机数去访问, 抽到空桶的概率很大.

BinaryHeap 是一个用二叉堆实现的优先队列 (priority queue), 其核心特点是:

  • 默认是大顶堆 (max-heap), 此时 pop() 总是弹出最大的元素

Fat Pointer

Fat Pointer (胖指针) 区别于普通 thin pointer:

  • Thin Pointer 只包含一个内存地址
  • Fat Pointer 除了包含内存地址, 还额外携带了一份元数据

之所以称为 “Fat”, 是因为在 64 位系统上, 普通指针占 8 字节, 而胖指针占 16 字节 (8+8), 占用的空间更大.

Fat Pointer 主要用来解决 DST (Dynamically Sized Type, 动态大小类型) 在编译期大小不确定的问题, 比如 [i32] 切片, 从类型上不知道大小, 编译器就没办法在栈上给它们分配空间.

DST 的大小实际上是知道的, 只是无法从类型上获取, 因此在编译期无法通过类型获取大小. 如果把这个具体的大小存到指针的部分空间里, 通过让指针的大小确定, 并且让 DST 的大小可以在运行时得到, 来解决这个问题.

Thin Pointer 与 Fat Pointer 的区分标准就是: 指向的类型在编译时大小是否确定, 如下面示例:

引用示例 指向的类型 类型是否 Sized 指针类型
&i32 i32 是 Thin Pointer
&[i32; 4] [i32; 4] 是 (固定长度数组) Thin Pointer
&[i32] [i32] 否 (切片) Fat Pointer
&str str 否 (字符串切片) Fat Pointer
&dyn MyTrait dyn MyTrait 否 (特征对象) Fat Pointer

131. 分割回文串

这道题我一开始的思路就有些问题, 我想要先找到所有的回文串, 但是是保存在一个 Vec<String> 里面, 之后取所有的子集, 然后答案就是每个子集搭配剩下单字符. 这个思路看似能做, 但实际上复杂度爆炸, 而且无法保证顺序与平台答案一致, 因为回文串单独摘出来了.

这个时候就该想, 不能把回文串单独 “摘出来”, 需要用索引和切片的形式表示. 一个回文串至少要两个索引, 我们是构建一个 Vec<(usize, usize)> 的数组吗? 还是别的形式? 此时就要思考别的条件, 拿到回文串之后又该如何做.

这里的思路是 “切分” (有点像排列组合里面的隔板法那种, 这个其实也不太好想到…), 每两个字母之间就有一个空隙可以放一个隔板 (可以切分), 我们对每个位置进行切分 (需要回溯), 如果切出来的左侧是一个回文串, 则继续递归切右边剩下字符串; 如果左侧不是回文串, 则这次切法不行, 直接跳过 (这些结合代码就要好理解一些). 我们着重需要关注的是: “判断左侧是否为回文串”. 如果之前回文串索引的存储形式是 Vec<(usize, usize)>, 那么我们需要遍历这个数组才能判断; 如果存储形式是 HashSet<(usize, usize)>, 似乎也行; 最轻量的方法是用 is_palindrome (Vec<Vec<bool>>) 数组, is_palindrome[i][j] == true 表示 s[i..j] 切片是一个回文串; false 则表示不是回文串.
