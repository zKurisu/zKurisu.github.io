child_exiting_tree 内置信号

child_exiting_tree 是 Node 的一个内置信号, 表示: “我的某个直接子节点即将离开场景树”. 该信号由父节点发出, 并且把即将离开的子节点作为参数传过来:

下面场景都会触发该 signal:

  • 子节点通过 queue_free() 被删除
  • 父节点调用 remove_child(child)
  • 整个父节点或关卡退出场景树 (因为子节点也会退出)

好处是可以让父节点统一管理子节点的退出, 比如:

  • 敌人管理器: 从维护的敌人列表中移除退出的敌人
  • 掉落物管理器: 清除已经离开场景的物品记录
  • UI 容器: 某个条目退出时, 清除选中状态或安排刷新统计信息

Godot Resource

在 Godot 中, Resource 是一个具体的基类, 表示 “能被编辑, 保存, 加载和共享的数据对象”, 纹理, 碰撞形状, 动画, 场景资源等都继承自它.

Node 通常参与 scene 的运行, 而 Resource 主要提供数据. Resource 也有方法, 信号和 setter 等, 但它不进入场景树, 也不会像节点一样自动执行 _ready(), _process().

Resource 通常有三种存在方式:

  • 保存为独立文件, 比如 sword.tres (.tres 保存文本格式资源), 保存一把剑的配置
  • 内嵌在 scene 文件里, 比如 *.tscn 中的 CollisionShape2D 的 shape 属性
  • 只存在于内存中, 比如用 RectangleShape2D.new() 创建

Node.process_mode

Node.process_mode 用来控制该节点的 process 函数是否运行, 有下面几种取值:

  • PROCESS_MODE_INHERIT, 往上找第一个非 Inherit 的祖先, 如果它的 process 运行, 那么当前节点也运行; 反之
  • PROCESS_MODE_PAUSABLE, 当 paused = true 时暂停; paused = false 是运行
  • PROCESS_MODE_WHEN_PAUSED, 在 get_tree().paused == true 时运行 (和上面一个反过来, 通常用于暂停菜单)
  • PROCESS_MODE_ALWAYS, 不管是否 pause 都运行 (通常用于音乐, 网络, 存档管理器)
  • PROCESS_MODE_DISABLED, 永远不跑

collision layer 和 mask

collision_layer 表示当前 node 对于其他 node 而言位于哪些碰撞层. collision_mask 表示当前 node 想要与哪些碰撞层碰撞.

deferred 是 “延迟的, 延后执行的” 的含义. set_deferred("disabled", true) 直译过来就是, 把 disabled 这个属性的赋值过程往后放, 不立刻做. 通常是把这一次 “赋值操作” 推到本帧末尾执行.

关键概念

在 Godot 中, 游戏是一棵由 nodes 构成的树, 节点可以分组形成 scenes, 还可以将 nodes 连接起来, 然后用 signals 通信.

Scene

Scene (场景), 指可以复用的组件. 可以是一个角色, 一件武器, 用户界面中的一个菜单, 一座房子, 整个关卡, 或者其他.

场景可以嵌套, 比如把一个角色放进关卡中 (关卡本身是一个 scene, 角色也是一个 scene).

Node

Scene 由一个或多个 nodes 组成. Node 是游戏中最小的构建块. 注意在编辑器中, scene 和 node 看起来是一样的, 因为一个 scene 就是一个 node tree, 子 node 会在编辑器中隐藏.

Scene tree

所有的 scene 汇聚为 scene tree, 其本质也是 node tree.

Signal

Node 在遇到某些事件时发出 signal. 此功能无需再代码中硬连接节点就能让它们相互通信.
