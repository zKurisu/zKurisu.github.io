1. 两数之和

这道题我的实现上有一些问题: 我一开始构建了一个 Hash Table, 把 nums 中所有 v -> i 的映射塞进去, 然后再遍历 nums 数组, 找 target - v 是否在哈希表中. 问题在于这会导致一个元素被重复使用, 比如 target = 6, nums = [3, 2, 4], 那么 6 - 3 = 3 在哈希表中, 得到的两个下标就是 [0, 0], 即被使用了两次.

正确的思路是直接遍历 nums, 先找 target - v 是否在 Hash 表中, 即当前元素与已插入元素交互, 找到了就返回, 不然再插入当前元素. 这样确保当前元素只与其在 nums 左侧的元素交互 (天然去重).

这里要注意两数之和的一个变体, 如果 nums 是已排序的, 此时找更好的方式就不是用哈希表了, 因为会引入 $O(N)$ 的空间复杂度. 需要借助有序数组的性质:

  • 最小的数在最左边 (left), 最大的数在最右边 (right)
  • 计算 sum = nums[left] + nums[right]:
    • 如果 sum < target, 说明现在的和太小了. 因为数组是有序的, 右边的数已经是最大了, 再往左移只会更小. 想要变大, 唯一的选择就是把左指针右移 (left++)
    • 如果 sum > target, 说明现在的和太大了, 唯一的选择就是把右指针左移 (right--)
    • 如果 sum == target, 此时找到一组解

这种也是双指针法.

207. 课程表

这道题明显要检测环, 但我显然也不知道如何检测 (

调查了下最直观的解题思路是 topological sort.

假设你当前拿到了一堆任务, 如果任务之间是没有依赖关系的, 就可以随便选取一个开始做. 但如果任务间有依赖, 此时还随机选择一个任务的话 (比如 “安装显卡驱动”), 可能没办法完成, 因为还没 “插上显卡”.

因此一个思考点是: 不能从任意节点开始, 必须要找到一个 “绝对安全, 不需要等待任何前置条件” 的起点. 而在 DAG (有向无环) 图中, 什么节点是不需要等待任何前置条件的呢? 即没有任何箭头指向它的节点 (indegree 为 0 的节点). 这也能得到一个推论: 在任何合法的依赖关系系统中, 必然存在至少一个 indegree 为 0 的节点, 如果一个都没有, 说明相互依赖, 形成死锁 (有环).

当完成一个 indegree 为 0 的任务后, 接下来该如何做呢? 比如做完了任务 A, 那么所有依赖 A 的后续任务 (比如 B 和 C), 它们对 A 的等待就结束了. A 在完成后, 在系统里的使命就结束了, 此时可以直接把 A 从图中抹去, 以及抹去从 A 发出的所有箭头. 而当抹去 A 和它的箭头后, 原本依赖 A 的节点 B 的 indegree 就会减少 1. 如果 B 的 indegree 减少到了 0, 那么 B 就变成了新的 “绝对安全起点”.

套到这道题中: 如果一门课的 indegree (入度) 为 0, 说明他没有任何前置要求, 可以直接修这门课.

代码思路是:

  1. 找到所有 indegree 为 0 的课程 (加入队列), 先修掉它们 (遍历队列)
  2. 修完一门课后, 把它指向的后续课程的 indegree 减 1 (代表前置要求完成了一项)
  3. 如果某门后续课程的 indegree 因此降到了 0, 说明它也变成了 “可修” 的状态, 加入队列

如果图中没有环, 则这个过程后, 所有课程都会被修完 (indegree 变成 0); 如果存在环, 环上的课程的 indegree 永远不可能降为 0, 因此他们永远不会进队列. 即最后修过的课程总数小于提供的总课程数.

实际实现中, 需要建立邻接表 (adjacent table, 存储一个任务指向的后续节点) 和入度表 (记录每个节点的 indegree) 来辅助.

4. 寻找两个正序数组的中位数

这道题的思考过程也挺重要的, 首先 merge 两个有序数组需要花 O(m + n) 的时间, 因此想要满足 O(log(m+n)) 的时间复杂度, 就不能够直接 merge.

一个思路是将题目进行转化, 原本是找 “中位数”, 现在可以等价为: 如何在两个有序数组中找到第 K 小的元素 (中位数的本质就是序列的第 k 个元素, 而在有序序列中, 就是第 k 小的元素).

  • 假如 m + n 为奇数, 那么 K 就为 (m + n + 1) / 2
  • 假如 m + n 为偶数, 那么需要求 K 就为 (m + n) / 2 和 (m + n) / 2 + 1 元素的平均值

由于我们不能一个一个进行比较, 需要用某种方法排除一些元素.

假设取 A 和 B 的第 k 个元素进行比较, 这个结果有意义吗? 此时相当于取了合并后序列的前 2k 个元素. 但实际上我们只需要前 k 个, 因此取 A 和 B 的第 k/2 个元素即可 (但答案不一定在这 k 个元素中, 比如 A 序列元素都比 B 小, 那么答案就是 A 的第 K 个元素, 这里取 k/2 肯定不包含. 这里的目的是排除一些元素而非直接找到答案).

  • 如果 A[k/2 - 1] 小于等于 B[k/2 - 1]. 说明 A 中的前 K/2 个元素, 最多也只能比 B 中的前 K/2 - 1 个元素大. 最大也只能排到第 K-1, 最小排到 K/2 (B 的所有元素都更大). 此时可以考虑去掉 A 的前 K/2 个元素 (相当于前 K 个去掉了 K/2 个, 但需要注意不是顺序排列的 K/2 个)
  • 接下来就需要从剩下的数组中找第 K/2 个元素, 问题规模更小了

同理如果 A[k/2 - 1] 大于 B[k/2 - 1], 则需要淘汰 B 的前 K/2 个元素.

初始化时, 这里先将 min_val 设置为 0.

push 时, 考虑这个流程:

  2. 先压入 diff, stack.push(diff)
  3. 然后根据 diff 的正负号判断是否需要更新 min: 如果 diff >= 0 则不需要更新, 否则 new_min = val, 注意这里的相关公式还有 diff = val - old_min; old_min = new_min - diff

需要额外注意, 当 stack.len() == 1 时一定要更新 min.

在 pop 时, 就能根据正负号判断是否有 min 的改变, 如果有, 则恢复出原来的 min 值:

  • pop 出的元素是正数, 说明没有发生 min 的改变, 不需要恢复
  • pop 出的元素是负数, 由 old_min = new_min - diff, 可以恢复出原来的 min 值

这里也需要注意, 当 stack.is_empty() 时, 需要将 min 设回 0.

top 需要注意 stack.len() == 1 的情况时, 直接返回 min.

295. 数据流的中位数

这道题顺着题干思考很容易出问题, 比如你会想插入一个元素后, 需要先完整排序, 然后取中位数.

但实际上这里我们不需要完整排序. 观察中位数的本质: 其就像一个 “切刀”, 把所有已排序的数字严格切成数量相等的左右两半.

如果只是找中位数, 我们并不需要左边或者右边完整排序:

  • 如果元素个数是奇数, 比如 5. 左边 3 个元素, 右边 2 个元素. 那么只需要找到左边的最大元素即可
  • 如果元素个数是偶数, 比如 6, 左边 3 个元素, 右边 3 个元素. 那么只需要找到左边的最大元素和右边的最小元素, 然后取平均即可

很明显, 大顶堆 (max heap) 能够以 O(1) 取得最大值; 小顶堆 (min heap) 能够以 O(1) 取得最小值.

因此这里只需要设计一个数据结构, 左边维护一个 max heap, 右边维护一个 min heap. 限制就是左边的元素必须全部小于右边的, 且数量平衡. 具体来说就是:

  • 假设总元素为 N 个
  • 若 N 为偶数, 此时两个堆数量相等 (small.len() == large.len())
  • 若 N 为奇数, 让 small 多维护一个元素 (small.len() == large.len() + 1)

插入新元素的时候有一个坑点需要注意:

  • 假设原来 small 中有 k 个元素, 此时插入一个新元素
  • 这个新元素有可能会大于 large 中的元素 (比如原来 small 中是 [1,2,3], 而 large 中是 [4,5,6], 此时向 small 插入 10)
  • 原来的 k 个元素肯定是小于 large 中元素的. 如果新元素大于 large 中的元素, 那么它肯定会出现在堆顶, 此时需要把堆顶搬到 large 中
  • 当堆顶插入到 large 中后, small 和 large 的有序关系又会恢复正确

75. 颜色分类

一个解法是 “荷兰国旗算法”, 这是 Dijkstra 提出的经典算法, 可以用 3 个指针将数组划分为四个区域:

  1. [0..p0): 全为 0 (红色区域)
  2. [p0..i): 全为 1 (白色区域)
  3. [i..p2]: 未处理区域
  4. (p2..len-1]: 全为 2 (蓝色区域)

i 负责扫描 [i..p2] 这个区间, 然后将每个元素放到对应的区域.

当 nums[i] == 1 (即遇到白色时), 由于白色区域本来就是 [p0..i), 此时只要 i 往右移动一步, 这个 1 就自然归入 [p0..1) 的范围内了.

当 nums[i] == 0 (即遇到红色, 需要放到最左边), 此时 i 在所有区域的中间, 要换到左边去, nums.swap(p0, i). 原来的 p0 位置是一个 1, 现在变成了 0, 而原来 i 的位置变成了 1. 由于 i 本来就挨着 1, 此时相当于把一个 1 从左边放到了右边. 之后需要让 p0 += 1 重新指向一个 1, i += 1 也要切换到下一个处理元素上.

同理当 nums[i] == 2 时 (遇到蓝色, 需要放到最右边), 需要 nums.swap(i, p2), 然后 p2 -= 1. 注意 i 此时不需要递增, 因为换过来的 p2 本来就是未处理部分.

算法的运作规则是维护指针 i:

  • 初始化 p0 = 0, p2 = nums.len() - 1, 指针 i = 0
  • 遍历指针 i, 当 i <= p2 时:
    • 遇到 0: 与 p0 位置交换, p0 和 i 各右移一步 (p0 += 1, i += 1)
    • 遇到 2: 与 p2 位置交换, p2 左移一步 (p2 -= 1)
    • 遇到 1: 无需交换, i 直接右移一步 (i += 1)

在大多数情况下, 感觉自底向上的迭代写法更简单:

一个比较取巧的方法是贪心 + 二分搜索. 比如我们先遍历整个 nums 数组一个一个处理, 以 [10, 9, 2, 5, 3, 7] 为例:

  1. 看见 10, 那么就有一个子序列 [10], 长度为 1
  2. 看见 9, 此时 [10,9] 是递减的, 此时子序列要么还是 [10] (长度为 1), 要么换为 [9] (长度还是 1), 此时想想, 换成 9 之后似乎没有什么坏处, 因为后续能接在 10 之后的, 也一定能接在 9 之后. 比如后面如果有 11, 那么 [10, 11] 序列长度为 2, [9, 11] 也为 2, 至少不会让子序列变短
  3. 看见 2, 也同理, 能够替换掉 9, [2] 子序列长度仍然是 1
  4. 看见 5, 此时 5 > 2, 可以接在 2 后面, 得到长度为 2 的序列 [2, 5]
  5. 看见 3, 3 < 5, 不能直接让子序列变长, 但 3 能接在 2 后面, 形成 [2, 3] 同样长度为 2, 并且更有可能得到更长的序列, 因此用 3 替换 5
  6. 看见 7, 7 > 3, 能接在 3 后面, 使序列长度变为 3

此时我们可以考虑收集的子序列的含义, [2] 子序列长为 1, 其变长的可能行在长度为 1 的子序列里面最大. 同理 [2,3], 也是在长度为 2 的子序列里最有可能变长. 如果 nums 遍历完之后得到了 [2,3,7], 由于不会再有新元素加入, 子序列长度最大也就是 3 了. 也就是说, 该收集的数组的长度就是这道题的解.

这里将这个数组名为 tails, 因为最后一个元素才能说明子序列的潜力, 最后一个元素越小, 越能形成更长的子序列. 并且 tails 的长度表示最有潜力的长度为 k 的子序列.

tails 数组是严格递增的, 数组的构建机制有两种:

  • push, 如果 v > last, 说明元素比当前子序列的最大元素还大, 追加能够增加长度了
  • replace, 如果 v < last, 说明其无法直接增加当前子序列的长度, 但是它可以替换 tails 中某一个元素, 比如 [2,5,7,9] 遇到 1, 能够改为 [1,5,7,9], 让 k = 1 的子序列的潜力变大

二分就体现在 replace 部分, 在严格递增的序列中找到第一个 > target 的 index.

最简单的思路是单向处理两次.

现在思考题目的两个核心规则:

  1. 每个孩子至少分配到 1 个糖果
  2. 相邻两个孩子评分更高的会获得更多糖果

“相邻” 包含了两个维度:

  • 左邻居, 如果 ratings[i] 比 ratings[i-1] 高, 他拿的糖果就要高于 i-1
  • 右邻居, 如果 ratings[i] 比 ratings[i+1] 高, 他拿的糖果就要高于 i+1

  • 顺序左遍历, 只看左邻居
